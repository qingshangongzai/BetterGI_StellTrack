## 文档信息

- **创建日期**: 2026-01-19
- **版本**: 1.0
- **目标**: 提升运行时效率,不影响功能逻辑
- **遵循规范**: `规范/开发规范.md`

---

## 一、优化概述

本优化计划旨在通过替换和优化现有函数,提升BetterGI星轨项目的运行时效率,同时确保不影响现有功能逻辑。优化将遵循项目的开发规范,保持代码的可维护性和一致性。

### 优化原则

1. **不改变功能逻辑**: 所有优化仅提升性能,不改变业务逻辑
2. **保持代码规范**: 严格遵循开发规范.md中的要求
3. **渐进式优化**: 分阶段进行,每个阶段可独立测试
4. **向后兼容**: 确保优化后的代码与现有代码兼容
5. **性能优先**: 优先优化高频调用和性能瓶颈函数

## 二、性能瓶颈分析

### 2.1 高频调用函数

通过代码分析,识别出以下高频调用函数:

| 函数名 | 调用频率 | 所在文件 | 性能问题 |
|--------|---------|---------|---------|
| `get_key_chinese_name()` | 高 | utils.py | 重复字典查找 |
| `generate_key_event_name()` | 高 | utils.py | 重复字典查找 |
| `get_event_data_from_table()` | 高 | utils.py | 逐行逐列获取数据 |
| `update_row_numbers()` | 中 | event_manager.py | 逐行更新 |
| `recalculate_relative_times()` | 中 | event_manager.py | 多次item()调用 |
| `save_state_to_undo_stack()` | 中 | state_manager.py | 遍历所有行收集数据 |
| `save_saved_state()` | 中 | state_manager.py | 遍历所有行收集数据 |
| `on_search_filter_complete()` | 中 | event_manager.py | 遍历所有行更新显示 |

### 2.2 性能问题分类

1. **重复计算**: 同一计算在循环中多次执行
2. **重复查找**: 字典查找在循环中重复执行
3. **频繁I/O**: 频繁的表格item()调用
4. **低效算法**: 使用低效的数据结构或算法
5. **内存分配**: 频繁的内存分配和释放

**优化后实现**:
```python
def get_event_data_from_table(table, row, skip_row_number=True):
    """从表格中获取事件数据 - 优化版本
    
    Args:
        table: 事件表格对象
        row: 行索引
        skip_row_number: 是否跳过行号列(默认True)
        
    Returns:
        list: 事件数据列表
    """
    start_col = 1 if skip_row_number else 0
    end_col = 8
    
    # 一次性获取整行数据
    event_data = []
    for col in range(start_col, end_col):
        item = table.item(row, col)
        event_data.append(item.text() if item else "")
    
    return event_data

def get_multiple_event_data_from_table(table, rows, skip_row_number=True):
    """批量获取多行事件数据 - 新增函数
    
    Args:
        table: 事件表格对象
        rows: 行索引列表
        skip_row_number: 是否跳过行号列(默认True)
        
    Returns:
        list: 多行事件数据列表
    """
    start_col = 1 if skip_row_number else 0
    end_col = 8
    
    # 批量获取多行数据
    all_data = []
    for row in rows:
        event_data = []
        for col in range(start_col, end_col):
            item = table.item(row, col)
            event_data.append(item.text() if item else "")
        all_data.append(event_data)
    
    return all_data
```

**预期收益**: 批量操作时性能提升约40%

```python
def recalculate_relative_times(self):
    if self.events_table.rowCount() == 0:
        return
    
    # 处理第一个事件:相对时间 = 绝对时间
    first_abs_time_item = self.events_table.item(0, 7)
    first_rel_time_item = self.events_table.item(0, 6)
    if first_abs_time_item and first_rel_time_item:
        first_abs_time = int(first_abs_time_item.text()) if first_abs_time_item.text().isdigit() else 0
        first_rel_time_item.setText(str(first_abs_time))
    
    # 从第二个事件开始,根据绝对时间计算相对时间
    for i in range(1, self.events_table.rowCount()):
        prev_abs_time_item = self.events_table.item(i-1, 7)
        prev_abs_time = int(prev_abs_time_item.text()) if prev_abs_time_item and prev_abs_time_item.text().isdigit() else 0
        
        curr_abs_time_item = self.events_table.item(i, 7)

        rel_time = curr_abs_time - prev_abs_time
        rel_time_item = self.events_table.item(i, 6)
        rel_time_item.setText(str(rel_time))
```

#### 3.2.4 优化 `on_search_filter_complete()` 函数

**当前实现**:
```python
def on_search_filter_complete(self, show_rows, hide_rows):
    self.events_table.setUpdatesEnabled(False)
    
    try:
        for row in range(self.events_table.rowCount()):
            should_show = row in show_rows
            self.events_table.setRowHidden(row, not should_show)
        
        self.update_stats()
    finally:
        self.events_table.setUpdatesEnabled(True)
```

**性能问题**: `row in show_rows` 使用列表查找,时间复杂度O(n)

**优化方案**: 将show_rows转换为集合,查找时间复杂度O(1)

**优化后实现**:
```python
def on_search_filter_complete(self, show_rows, hide_rows):
    """搜索过滤完成回调 - 优化版本"""
    # 将show_rows转换为集合,提升查找性能
    show_rows_set = set(show_rows)
    
    self.events_table.setUpdatesEnabled(False)
    
    try:
        for row in range(self.events_table.rowCount()):
            should_show = row in show_rows_set
            self.events_table.setRowHidden(row, not should_show)
        
        self.update_stats()
    finally:
        self.events_table.setUpdatesEnabled(True)
```

**预期收益**: 大量行过滤时性能提升约70%

#### 3.3.2 提取重复的状态收集逻辑

**当前问题**: `on_undo()`、`on_redo()` 和 `save_saved_state()` 中都有重复的状态收集逻辑

```python
def _collect_all_events_data(self):
    """收集所有事件数据 - 通用函数
    
    Returns:
        list: 所有事件数据列表
    """
    table = self.parent_window.event_manager.events_table
    row_count = table.rowCount()
    
    all_events = []
    for row in range(row_count):
        event_data = []
        for col in range(1, 8):
            item = table.item(row, col)
            event_data.append(item.text() if item else "")
        all_events.append(event_data)
    
    return all_events

def on_undo(self):
    """撤销操作 - 优化版本"""
    if not self.undo_stack:
        self.parent_window.status_bar.showMessage("⚠️ 没有可撤销的操作")
        return
    
    # 使用通用函数收集当前状态
    current_state = {
        'events': self._collect_all_events_data()
    }
    self.redo_stack.append(current_state)

    previous_state = self.undo_stack.pop()
    self._restore_state(previous_state)

    self.save_saved_state()

    self.parent_window.status_bar.showMessage("✅ 已撤销操作")
    self.debug_logger.log_info("已撤销操作")

def on_redo(self):
    """重做操作 - 优化版本"""
    if not self.redo_stack:
        self.parent_window.status_bar.showMessage("⚠️ 没有可重做的操作")
        return
    
    # 使用通用函数收集当前状态
    current_state = {
        'events': self._collect_all_events_data()
    }
    self.undo_stack.append(current_state)

    next_state = self.redo_stack.pop()
    self._restore_state(next_state)

    self.save_saved_state()

    self.parent_window.status_bar.showMessage("✅ 已重做操作")
    self.debug_logger.log_info("已重做操作")

def save_saved_state(self):
    """保存当前状态到文件 - 优化版本"""
    try:
        logs_dir = os.path.join(get_user_data_dir(), "logs")
        
        if not os.path.exists(logs_dir):
            os.makedirs(logs_dir, exist_ok=True)

        state_file = os.path.join(logs_dir, "BetterGI_StellTrack_state.json")
        self.debug_logger.log_info(f"尝试将状态保存到 {state_file}")

        state = {
            'events': self._collect_all_events_data(),
            'settings': {
                'loop_count': self.parent_window.settings_panel.loop_count_input.value(),
                'interval': self.parent_window.settings_panel.interval_input.value(),
                'time_unit': self.parent_window.settings_panel.time_unit_combo.currentText(),
                'width': self.parent_window.settings_panel.width_input.text(),
                'height': self.parent_window.settings_panel.height_input.text(),
                'scale': self.parent_window.settings_panel.scale_combo.currentText()
            }
        }

        collected_event_count = len(state['events'])
        if collected_event_count != self.parent_window.event_manager.events_table.rowCount():
            self.debug_logger.log_error(f"收集事件数据时出现不一致")
            return False

        state_dir = os.path.dirname(state_file)
        if not os.path.exists(state_dir):
            os.makedirs(state_dir)
            self.debug_logger.log_info(f"已创建状态文件目录: {state_dir}")

        try:
            with open(state_file, 'w', encoding='utf-8') as f:
                json.dump(state, f, ensure_ascii=False, indent=2)
            
            self.debug_logger.log_info(f"状态已成功保存到文件: {state_file}，包含 {collected_event_count} 个事件")
            return True
        except IOError as e:
            self.debug_logger.log_error(f"写入状态文件失败: {e}")
            return False
        except json.JSONDecodeError as e:
            self.debug_logger.log_error(f"序列化状态数据失败: {e}")
            return False
    except (OSError, ValueError) as e:
        self.debug_logger.log_error(f"保存状态到文件失败: {e}", exc_info=True)
        return False
```

   ```python
   def recalculate_relative_times(self):
       """重新计算所有事件的相对时间，保持绝对时间不变
       
       第一个事件的相对时间等于绝对时间。
       从第二个事件开始，根据绝对时间计算相对时间：
       相对时间(n) = 绝对时间(n) - 绝对时间(n-1)
       """
       if self.events_table.rowCount() == 0:
           return
       
       self.events_table.setUpdatesEnabled(False)
       
       try:
           # 处理第一个事件：相对时间 = 绝对时间
           first_abs_time_item = self.events_table.item(0, 7)
           first_rel_time_item = self.events_table.item(0, 6)
           if first_abs_time_item and first_rel_time_item:
               first_abs_time = int(first_abs_time_item.text()) if first_abs_time_item.text().isdigit() else 0
               first_rel_time_item.setText(str(first_abs_time))
           
           # 从第二个事件开始，根据绝对时间计算相对时间
           for i in range(1, self.events_table.rowCount()):
               # 获取前一个事件的绝对时间
               prev_abs_time_item = self.events_table.item(i-1, 7)
               prev_abs_time = int(prev_abs_time_item.text()) if prev_abs_time_item and prev_abs_time_item.text().isdigit() else 0
               
               # 获取当前事件的绝对时间
               curr_abs_time_item = self.events_table.item(i, 7)
               curr_abs_time = int(curr_abs_time_item.text()) if curr_abs_time_item and curr_abs_time_item.text().isdigit() else 0
               
               # 计算并更新相对时间
               rel_time = curr_abs_time - prev_abs_time
               rel_time_item = self.events_table.item(i, 6)
               rel_time_item.setText(str(rel_time))
       finally:
           self.events_table.setUpdatesEnabled(True)
   ```

### 9.1 隔行删除事件时相对时间更新问题修复 (已完成)

**修复日期**: 2026-01-20

**问题描述**:
当使用"仅修改当前事件时间"选项执行隔行删除操作时，只有第一个被删除事件后续事件的相对偏移时间被正确更新，而后续被删除事件的后续事件相对偏移时间未能同步更新。

**根本原因**:
1. 原始代码只处理了第一个被删除事件的情况，没有考虑所有被删除事件的影响
2. 当删除多个事件时，行号会发生变化，导致后续事件的相对时间计算错误
3. 优化方案只更新了第一个被删除事件后的第一个事件的相对时间，忽略了后续被删除事件的影响

**修复方案**:
1. **全面处理所有被删除事件**：找出所有被删除事件后的第一个未被删除事件
2. **精确计算相对时间**：为每个这样的事件重新计算相对时间
3. **避免重复更新**：确保同一个事件的相对时间不会被重复计算
4. **保持性能优化**：只更新必要的相对时间，避免不必要的计算

**实现细节**:
1. **收集所有被删除行号**：将选中的行号转换为删除前的行号（从1开始）
2. **找出需要更新的行号**：遍历所有被删除的行号，找出每个被删除事件后的第一个未被删除事件
3. **去重和排序**：确保需要更新的行号不重复，并按顺序处理
4. **计算新的相对时间**：对于每个需要更新的行号，找出其前一个未被删除的行，计算新的相对时间
5. **更新表格**：将计算出的新相对时间更新到表格中

**代码位置**:
- 文件: `managers/event_manager.py`
- 方法: `on_delete_event()`
- 行号: 1621-1686

**性能优化**:
1. **最小化计算范围**：只计算需要更新的相对时间，而不是所有剩余事件
2. **避免重复计算**：通过去重确保同一个事件的相对时间不会被重复计算
3. **使用删除前数据**：使用删除前的事件数据来计算，避免行号变化的影响

**遵循的规范**:
- ✅ 严格遵循 `开发规范.md` 的要求

```python
    def _get_style_from_cache(self, style_key):
        """从缓存获取样式,如果缓存失效则重新生成"""
        cache_key = f"{self.theme_mode}_{style_key}"
```
